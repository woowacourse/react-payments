# 페이먼츠 미션

## 기능 요구 사항

### 카드사 선택

- [x] 사용자는 카드사를 선택할 수 있고, 선택에 따라 프리뷰 카드의 색상이 변경된다.

### 카드 번호 입력 및 식별

- [x] 카드 번호는 4자리씩 4개의 input으로 입력받는다
- [x] 입력은 숫자만 가능하고 유효하지 않은 번호 입력시 피드백을 제공한다.

### 카드 유효기간 입력

- [x] 카드 유효기간은 월 2자리와 년도 2자리를 각각 별도의 input으로 입력받는다.
- [x] 입력은 유효한 월과 년도만 입력가능하도록 제한한다.

### CVC

- [x] CVC는 숫자 3자리만 입력 가능하다.
- [x] 유효하지 않은 번호 입력시 제한한다.

### 실시간 프리뷰 업데이트

- [x] 사용자가 입력하는 카드 번호를 실시간으로 파악하여 해당 브랜드를 UI에 표시한다.
  - [x] Visa, Mastercard
  - [x] AMEX, Diners, UnionPay

### 폼 제출 및 상태 관리

- [x] 모든 카드 정보가 정확하게 입력되고 검증되었을 때 확인 버튼이 활성화된다.
- [x] 입력한 정보 중 하나라도 지우거나 수정하여 유효하지 않게 되면 확인 버튼은 비활성화된다.

### 카드 등록 (서버 연동)

- [x] 등록 버튼 클릭 시 `POST /cards`로 카드 정보를 전송한다.
- [x] 201 응답 수신 시 카드 목록 페이지(`/cards`)로 이동한다.
- [ ] 서버가 `400 { code, message }`를 반환하면 `code`를 해당 입력 필드로 매핑하여 그 필드 아래에 메시지를 표시한다.

### 카드 등록 완료 및 네비게이션

- [x] 확인 버튼을 클릭하면 사용자는 카드 등록 완료 페이지로 이동한다.
- [x] 카드 등록 완료 페이지에서는 카드 등록이 성공적으로 완료되었다는 메시지와 함께, 다시 카드 등록 페이지로 돌아갈 수 있는 확인 버튼을 제공한다.

### 카드 목록 (`/cards`)

- [x] 페이지 진입 시 `GET /cards`로 등록된 카드 목록을 조회한다.
  - 비동기 상태(`idle | loading | success | error`)에 맞는 UI를 표시한다.
  - loading: 스피너 또는 스켈레톤
  - success + 목록이 비어 있음: "등록된 카드가 없습니다" 안내
  - success + 목록이 있음: 카드 프리뷰 리스트
  - error: 에러 메시지와 재시도 버튼

### 카드 삭제

- [x] 각 카드에 삭제 버튼을 제공한다.
- [x] 삭제 버튼 클릭 시 `window.confirm()`으로 확인을 받고, 사용자가 확인한 경우에만 삭제를 진행한다.
- [x] 확인 시 `DELETE /cards/:id`로 요청하고 목록을 갱신한다. 취소 시 아무 요청도 보내지 않는다.

## 프로그래밍 요구 사항

### 1단계

- Storybook을 이용하여 컴포넌트의 다양한 상태를 테스트한다.
- 에러 처리 로직을 명확하게 작성하여 코드의 가독성을 높인다.
- 반복되는 컴포넌트와 스타일은 분리하여 재사용성을 높인다.

### 2단계

#### Routing

- react-router를 이용하여 페이지를 관리한다.

#### Custom Hooks

- Custom Hook을 활용하여 Form 관리 로직을 UI와 분리한다.
- 처음부터 훅 구조를 설계하지 않는다. 먼저 1단계 스타일로 완성한 뒤 중복을 확인하고 추출한다.

#### Test

- 각 스토리에 명확한 이름을 지정하여 컴포넌트의 사용 사례를 쉽게 이해할 수 있도록 한다.

### 3단계

#### MSW

- `POST /cards`, `GET /cards`, `DELETE /cards/:id` handler를 작성한다.
- `POST /cards`에 400 시나리오(지원하지 않는 카드사 등)를 추가한다.

#### Async State

- 비동기 상태를 `idle | loading | success | error` 네 가지로 명시적으로 다룬다.
- `isLoading`, `error`를 별도 boolean으로 분리하지 않는다.

#### Test

- MSW와 RTL로 사용자 관점의 통합 테스트를 작성한다.
